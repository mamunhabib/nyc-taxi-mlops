## 2. Implementation Architecture & Phases

### PART 1: Platform Foundation (MLOps Track)

#### Pre-existing Infrastructure [COMPLETED]
* **Kubernetes Cluster (OrbStack / Mac):** Local container & K8s runtime.
* **Jenkins Automation Server:** CI/CD orchestration server configured with `Asia/Kuala_Lumpur` timezone (`http://localhost:8081`).
* **Kibana & Elasticsearch:** Centralized logging stack configured with browser-matched timezone (`http://localhost:8084`).

#### Layer 1: Dedicated Platform Services (`k8s/platform/`) [COMPLETED]
* `k8s/platform/00-namespace.yaml`: Dedicated namespace `nyc-taxi-mlops`.
* `k8s/platform/01-configmap.yaml`: Cluster DNS endpoints, S3 bucket, ports, and `TZ: Asia/Kuala_Lumpur`.
* `k8s/platform/02-postgres.yaml`: PostgreSQL 15 deployment with 2 GiB PVC for MLflow & drift metrics.
* `k8s/platform/03-minio.yaml`: MinIO S3 object store with 5 GiB PVC (S3 port 9000 & console port 8088).
* `k8s/platform/04-mlflow.yaml`: MLflow Tracking Server & Model Registry on port 8087.
* `k8s/platform/05-evidently.yaml`: Evidently Web UI Deployment & Service on port 8086 with persistent workspace.
* `k8s/platform/06-kibana-dashboard.yaml`: Automated Kubernetes setup Job importing 10 saved objects (index patterns, metric gauges, request histogram, and donut charts) into Kibana.

---

### PART 2: Model & Data Development (ML Engineering Track)

#### Phase 0: Scaffolding & Zero-Data-in-Git Policy [COMPLETED]
* Established a strict **pure code repository** architecture.
* `.gitignore` and `.dockerignore` ensure no raw datasets (`data/raw/`), intermediate pickles (`data/processed/*.pkl`), reference datasets (`data/reference.parquet`), or model binaries (`models/*.pkl`) are stored in version control.

#### Phase 1: Automated On-Demand Data Ingestion [COMPLETED]
* `src/utils.py`: Added `ensure_raw_dataset(filepath)`. When any raw monthly dataset is requested during CI/CD or local testing, it is automatically fetched via HTTP from the official NYC TLC CloudFront repository:
  * `https://d37ci6vzurychx.cloudfront.net/trip-data/green_tripdata_2023-01.parquet` (Jan: Train)
  * `https://d37ci6vzurychx.cloudfront.net/trip-data/green_tripdata_2023-02.parquet` (Feb: Validation & tuning)
  * `https://d37ci6vzurychx.cloudfront.net/trip-data/green_tripdata_2023-03.parquet` (Mar: Production stream & drift test)

#### Phase 2: In-Container Preprocessing & Feature Engineering [COMPLETED]
* `src/data_prep.py`: Computes trip duration, filters outliers ($1 \le \text{duration} \le 60$ min, $0 < \text{trip\_distance} \le 50$ mi), and engineers route interaction features (`PU_DO`).
* Preprocessing runs dynamically inside the CI/CD runner container without requiring any manual local runs.
* `DictVectorizer` (`dv.pkl`) is fitted dynamically from the training split during pipeline runs.

#### Phase 3: Multi-Model Experimentation & Champion Selection [COMPLETED]
* `config/model_config.yaml`: Candidate model parameters for Ridge Regression, Random Forest Regressor, and XGBoost.
* `src/train.py`: Unified multi-model training engine with MLflow tracking.
* Champion Selection: Automatically selects candidate with lowest validation RMSE and promotes it to `@champion` alias in the MLflow Model Registry.
* Generates `models/model.pkl` and `data/reference.parquet` directly from the retraining run.

---

### PART 3: Serving, Observability & CI/CD/CT (MLOps Track)

#### Milestone 3.5: CI/CD Unit Testing [COMPLETED]
* `tests/test_data_prep.py`: Self-contained unit tests using mock DataFrames generated in temporary directories (`tmp_path`). Runs in 0.64s in the CI/CD runner without external data dependencies.

#### Phase 4: Containerized Model Serving [COMPLETED]
* `serving/schemas.py`: Pydantic input contract (`PULocationID`, `DOLocationID`, `trip_distance`).
* `serving/app.py`: FastAPI inference engine exposing `POST /predict` and `GET /health`.
  * Checks for local model binary `models/model.pkl` first.
  * Dynamically falls back to loading `@champion` directly from MLflow Registry via `mlflow.pyfunc.load_model`.
* `serving/Dockerfile`: Lightweight production serving image incorporating freshly extracted `model.pkl` and `dv.pkl`.

#### Phase 5: Decoupled User Interface (Streamlit Frontend) [COMPLETED]
* `ui/app.py`: Modern Streamlit interactive passenger/dispatcher web app querying FastAPI for real-time predictions.
* `ui/Dockerfile`: Dedicated frontend container exposing port 8501.
* `k8s/apps/ui.yaml`: Streamlit Deployment & LoadBalancer Service on port 8089 communicating with FastAPI via internal K8s DNS (`http://nyc-taxi-serving:8000`).

#### Phase 6: Drift Monitoring, Continuous Streaming & Observability [COMPLETED]
* `config/monitoring_config.yaml`: Evidently drift configuration (30% feature drift threshold, $p=0.05$).
* `k8s/streamer-pod.yaml`: Standalone, self-contained Kubernetes traffic generator pod running in `nyc-taxi-mlops`.
  * Contains ConfigMap with 750 genuine Q2 2023 taxi trips (April, May, June) extracted from NYC TLC data (`data/q2_samples.json`).
  * Continuously streams requests to `http://nyc-taxi-serving:8000/predict` at ~2 req/sec.
* `monitoring/drift_detector.py`: Evidently AI service computing multi-column drift and updating 5 live panels in Evidently UI.
* `monitoring/db.py`: PostgreSQL client recording drift metrics for audit logs and retraining triggers.
* `k8s/platform/06-kibana-dashboard.yaml`: Automated setup Job importing comprehensive Kibana visualization dashboard.

#### Phase 7: Automated CI/CD & Drift-Gated Continuous Training (Option B) [COMPLETED]
* `Dockerfile.runner`: Embedded codebase image enabling fully autonomous testing and retraining within Kubernetes Jenkins without host volume mount dependencies.
* `Jenkinsfile`: 7-stage automated pipeline triggered on Git push:
  1. **Unit Testing:** Builds runner container, executes pytest suite.
  2. **Continuous Training & Drift Check:** Runs `pipelines/training_flow.py` inside runner:
     * Ingests raw data on demand.
     * Fits `DictVectorizer` and generates splits dynamically.
     * Evaluates production drift against baseline.
     * Retrains Ridge, RF, XGBoost models upon drift detection (>30% threshold).
     * Promotes new champion to `@champion` alias in MLflow.
     * Extracts `models/model.pkl` and `data/processed/dv.pkl` to workspace.
  3. **Build Docker Images:** Builds `nyc-taxi-serving` and `nyc-taxi-ui`.
  4. **Push to GHCR:** Pushes images to GitHub Container Registry using credentials.
  5. **Clean Local Images:** Prunes local Docker cache to guarantee fresh Kubernetes image pulls.
  6. **Deploy to Kubernetes:** Applies manifests and executes zero-downtime rolling restart.
  7. **Smoke Test & Verification:** Queries `http://localhost:8085/health` to confirm successful deployment.
* **Timezone Alignment:** Full synchronization of host, Jenkins server, Kubernetes pods, and logging stack to `Asia/Kuala_Lumpur` (`UTC+8`).
